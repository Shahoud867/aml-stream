# aml-stream: decision horizons in graph-based anti-money-laundering

Research code, documents and paper source for a Computer Networks project (FAST NUCES, Semester 7). The question: **what does an AML detector know when it decides, and is the decision early enough to stop the money?** Published results on the AMLworld benchmark let each test transaction see later transactions, on a test set that runs past the end of normal traffic. This repository measures what that costs, audits the published models, and tests timing-only attacks and timing-invariant detection.

**Status (4 November 2026).** The shared code and its tests are done. The experiments are only starting: no official-model result and no confirmatory result exists yet, so nothing here is a finished finding. Exact status per component is in [`docs/NOTEBOOK_METHODOLOGY.md`](docs/NOTEBOOK_METHODOLOGY.md) section 8, and the plan and schedule are in [`docs/ROADMAP.md`](docs/ROADMAP.md).

## Layout

| Path | What it holds |
|---|---|
| `src/amlh/` | The research package: data preparation, horizon view and features, detectors, attacks, metrics, job runner, notebook session, merge step |
| `tests/` | 302 tests. Official Multi-GNN and FraudGT code is never run by them |
| `notebooks/` | Five experiment notebooks and a merge notebook for Kaggle or Colab, generated by `scripts/build_notebooks.py`. Run guide: [`notebooks/README.md`](notebooks/README.md) |
| `scripts/` | Notebook builder, code packager, analysis (`08_analyze.py`), tail audit; `legacy/` holds superseded scripts that earlier results came from |
| `docs/` | The research record: plan, frozen hypotheses, definitions, roadmap, notebook design, code map. `course/` has the assignment briefs, `archive_rev2/` the superseded versions |
| `paper/` | LaTeX source of the literature review and methodology (Revision 3), bibliography, generated tables and figures, and the compiled PDF |
| `results/` | Small result files and figures from the HI-Small discovery runs |
| `third_party/` | Official Multi-GNN and FraudGT as read-only submodules, at pinned commits |
| `dist/` | The code package uploaded to Kaggle or Drive, named by its code hash |

## Setup

```bash
git clone --recurse-submodules https://github.com/Shahoud867/aml-stream.git
cd aml-stream
python -m venv .venv && . .venv/bin/activate          # on Windows: .venv\Scripts\activate
pip install -r requirements-kaggle.txt
pip install torch --index-url https://download.pytorch.org/whl/cpu   # the TD-GNN tests need torch
python -m pytest tests -q
```

The full suite takes about 6 minutes. Tests that need the submodules skip themselves when they are absent. LightGBM is pinned to 4.6.0 because 4.7.0 crashed on trivial data.

## Data

The data is not in this repository (6.8 GB). The four AMLworld datasets come from the Kaggle dataset `ealtman2019/ibm-transactions-for-anti-money-laundering-aml`, and SAML-D from `berkanoztas/synthetic-transaction-monitoring-dataset-aml`. Row counts and SHA-256 hashes are in `docs/SPEC.md` section 2, and every run checks them, because one download endpoint has silently truncated a file.

## Running the experiments

The experiments run in the five notebooks on Kaggle or Colab, not on a laptop. Follow [`notebooks/README.md`](notebooks/README.md): pilot each notebook first, then run production, then merge.

After any change to `src/` or `scripts/` the code hash changes, and every notebook refuses to run a different version. Rebuild both together:

```bash
python scripts/build_notebooks.py
python scripts/make_code_dataset.py dist
```

A test fails if the committed notebooks do not carry the current code hash.

## Rules

- Every reported number comes from a log through `scripts/08_analyze.py`.
- HI-Small is the discovery set. A claim counts as confirmed only on data not modelled when the hypotheses were frozen.
- Never put a token in code or a notebook.
- Official third-party code stays read-only. Notebooks clone it at the pinned commits.
